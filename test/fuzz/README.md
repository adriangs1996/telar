# Telar AFL++ fuzzing

This package keeps fuzzing outside the normal Telar build. It builds small
instrumented executables for byte-stream boundaries owned by Telar:

- `schema-client`: decodes client IPC messages and exhausts lazy launch
  argument and environment iterators.
- `schema-server`: decodes server IPC messages and exhausts lazy snapshot and
  list iterators.
- `escape`: exercises history escape scanners and checks that chunked input
  produces the same observable state as whole-buffer input where the scanner API
  supports slices.

Install AFL++ and LLVM tooling first:

```sh
brew install afl++ llvm lld
# or, on Ubuntu:
sudo apt-get install afl++ llvm lld
```

On macOS, the run steps set
`AFL_I_DONT_CARE_ABOUT_MISSING_CRASHES=1` so AFL++ can start without changing
the system crash reporter. For strict crash reporting, run AFL++'s
`afl-system-config` yourself and accept its system-wide changes.

Build the harnesses and replay the seed corpus:

```sh
cd test/fuzz
zig build check -Doptimize=Debug
```

Run one fuzzing campaign:

```sh
cd test/fuzz
zig build run-schema-client -Doptimize=Debug
zig build run-schema-server -Doptimize=Debug
zig build run-escape -Doptimize=Debug
```

The generated binaries are installed as:

```text
zig-out/bin/fuzz-schema-client
zig-out/bin/fuzz-schema-server
zig-out/bin/fuzz-escape
```

Crash replay is plain stdin:

```sh
zig-out/bin/fuzz-schema-client < afl-out/schema-client/default/crashes/id:...
```

The initial corpus is generated by `build.zig`. AFL++ output goes under
`afl-out/` and is intentionally ignored. Malformed decode errors are normal;
crashes, hangs, safety panics, and property mismatches are findings.

The C glue under `afl/` is derived from Ghostty's AFL++ package, itself based
on `zig-afl-kit`, and remains development-only. It is never linked into Telar's
runtime or client binaries.
