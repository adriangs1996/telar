telar machine add: Save a machine: a label and the address its gateway pairs with

Usage: telar machine add LABEL ADDRESS [--color COLOR] [--disabled] [--check] [--setup [--binary PATH] [--skip agents,config,login,editor]] [--json]

Arguments:
  ADDRESS          What `telar server pair` (or `enable`) printed on that machine,
                   `telar://HOST:PORT#KEY.CODE`; quote it. An address without its
                   code, as `machine list` shows it, saves a machine this one is
                   already paired with. Unique.
  --color COLOR    `#RRGGBB` or a lowercase name, for the window's chrome.
  --disabled       Save it without windows connecting to it; dispatch still works.
  --check          Reach the machine first (as `machine check`) and refuse an
                   unreachable one.
  --setup          Set it up right after saving (as `machine setup`), with its options.

Effects: presents the code to the gateway at the address, which checks it holds KEY
and from then on admits this machine by its own key; the code is spent. Then writes
machines.json atomically, with the address and without the code. With --check or
--setup the machine's runtime is started as `check` does.

Results: nothing, or the check/setup report (JSON with --json). Exit 0; 1 with the
reason on stderr (taken label or address, invalid label, a code that was used or
expired, a gateway that does not answer or holds another key).
